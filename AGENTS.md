# Working in this repository (humans and AI agents)

This file is the contract for anyone — human or AI coding agent (Claude, Codex,
...) — sending changes to the runtz CLI. Agents: read this before opening a PR.

## Repository layout

- `cmd/runtz/` — CLI entrypoint and command wiring.
- `internal/` — scanners (`sca`, `sast`, `pkgscan`, `k8s`), the platform client
  (`runtzclient`), the CI/CD severity `gate`, and the `update` self-updater.

The web platform and backend engine live in
[runtz-dev/runtz](https://github.com/runtz-dev/runtz).

## Branch and release flow

```
feature branch ──▶ main ──▶ publish release vX.Y.Z
   (your work)                  (goreleaser + image)
```

- Branch off `main`. Open pull requests **against `main`**.
- Release Drafter keeps a draft release up to date from merged PRs. Publishing
  it builds the binaries (GitHub Releases) and the `runtzdev/runtz-cli` image.
- Label PRs (`feature`/`fix`/`chore`/etc.) so Release Drafter categorizes and
  version-bumps correctly.

## Checks to run before opening a PR

```bash
go vet ./...
go test ./...
go build ./cmd/runtz
```

Keep changes scoped and match existing patterns in each package.

## Hard rules

- **Never commit secrets, tokens or personal endpoints.** Use `--token`/
  `RUNTZ_TOKEN` at runtime.
- Keep the exit-code contract stable: `0` success, `1` execution error, `2` usage
  error, `3` severity gate tripped / update available. CI pipelines depend on it.
- New scan commands must wire the shared `gate` thresholds so the CI/CD gates
  work everywhere.
- Update docs (README / site) when flags or behavior change.

## Pull requests

Fill the **Generated by** section of the pull request template. If an agent
wrote the change, name the agent and model, the task it was given, and how it was
verified (tests run, binary exercised). A human must review the full diff and is
accountable for it.
